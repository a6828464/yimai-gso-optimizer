# 公众号正文渲染器规则

把 WordPress 文章正文转成微信公众号草稿箱能接受的 HTML。实现：`includes/class-wechat-renderer.php`（`YIMAI_GSO_Wx_Renderer`）。

对外只有两个方法：

| 方法 | 用途 | 是否调微信接口 |
| --- | --- | --- |
| `render( WP_Post $post )` | 生成可直接提交 `draft/add` 的正文 | 是（图片要转存到微信） |
| `render_preview( WP_Post $post )` | 后台预览排版 | 否，图片保留原 src |

`render()` / `render_preview()` 失败时返回 `WP_Error`，message 一律是给运营看的中文（例：「正文超过 20000 字，微信拒收，请拆分为上下篇」）。
图片转存告警（哪张图没成功、超量图片）通过 `YIMAI_GSO_Wx_Renderer::get_warnings()` 取，每次 render 开头重置。

---

## 一、规则与对应的微信限制

微信正文不是网页：它按**受限 HTML 子集 + 内联 style** 清洗，任何「够不着」的特性都会被静默剥掉，所以每一条规则都对应一个具体的坑。

| # | 规则 | 具体做法 | 不做会怎样（微信限制） |
| --- | --- | --- | --- |
| 1 | 取源用 `the_content` | `apply_filters( 'the_content', $post->post_content )`，临时挂全局 `$post` 再还原 | 直接用 `post_content` 会带出 `<!-- wp:paragraph -->` 区块注释和未渲染的短代码，草稿里出现「半截文字」 |
| 2 | 解析补编码声明 | `loadHTML( '<?xml encoding="utf-8"?><div id="wx-root">' . $html . '</div>' )` + `LIBXML_HTML_NOIMPLIED \| LIBXML_HTML_NODEFDTD` | libxml 会按 ISO-8859-1 猜编码，整篇中文变乱码 |
| 3 | 根节点兜底 | 先 `getElementById('wx-root')`，拿不到再用 XPath `//*[@id="wx-root"]` | 换 libxml 版本后 `getElementById` 可能返回 null，整篇静默变空 |
| 4 | 整节点删除 | `script / style / iframe / form / input / button / noscript / svg / audio / video` | 微信本来就会剥掉这些，但残留的空 `<p>`、`<svg>` 占位会把上下间距撑乱；`on*` 之类事件属性还可能被判定为风险内容 |
| 5 | 标签白名单 + unwrap | 只留 `section p span img a strong em b i br hr blockquote ul ol li h1-h6 table thead tbody tr th td pre code figure figcaption`，其余标签 unwrap（子节点前移、丢掉标签） | `div` / `article` / `main` 这类容器被微信剥掉后，里面的文字会挤成一段；Gutenberg 一个段落一个 `div`，不 unwrap 就是「全文粘连」 |
| 6 | 属性白名单 | 只留 `src href alt colspan rowspan`，其余（`class` `id` `data-*` `on*` `style`）先全删 | 微信只认内联 `style`，`class` / 外部样式表一律被剥，作者的 `style` 里还常有 `float` / `width` / `position` 会把手机排版撑破 |
| 7 | 样式内联 | 清完属性后按标签查 `STYLE` 表重建 `style`（见第二节） | 没有内联样式 = 全文一个字号、一个行高，标题和正文分不出来 |
| 8 | 图片转存 | 下载 → `wp_get_image_editor` 压缩 → `uploadimg` → 换 src（见第三节） | 微信不显示外链图片，草稿箱里全是白框 |
| 9 | 链接转 span | 站内 / 站外都换成 `<span style="color:#576b95">文字</span>`，站外 URL 收进文末脚注 | 微信正文不支持外链跳转（订阅号连外链入口都没有），留着 `<a>` 能点但点了没反应，读者以为文章坏了 |
| 10 | 代码块转义 | `pre` 内部整体按纯文本处理并实体转义（见第五节） | 作者在 `pre` 里裸写 `<div>` 时，解析器把它变成真实元素，微信清洗后代码块只剩半截文字 |
| 11 | 整体包裹 | 外层 `<section style="font-size:16px;line-height:1.75;color:#3f3f3f;word-break:break-word">` | 微信默认字色偏浅、行距紧；`word-break` 缺失时长英文 / URL 会横向撑破手机宽度 |
| 12 | 长度闸门（两道） | 前置粗估：解析前按纯文本字数拦 > 20000 字；末尾精确：清洗后的纯文本 > 20000 字 → `wx_too_long`、HTML > 1MB → `wx_too_big` | 超限时微信**静默拒收**或返回 53503，运营只看到「同步失败」却不知道原因。前置那道是为了不白烧配额：图片流水线是**真的往微信传图**，只留末尾闸的话，一篇 25000 字的文章会先把 N 张图全传完、耗掉 uploadimg 日配额、花几十秒，最后才报超长 |

安全与稳定性细节：

- 遍历 DOM 用 `while` + 活 `childNodes` 索引，删节点 / unwrap 后索引不推进，天然重新处理被提升的节点，不会出现 NodeList 错位。
- 属性、图片都用 `getAttribute` / `setAttribute` / `removeAttribute`，没有任何一处用正则改 HTML。
- 注释节点（区块注释、`<!--more-->` 残留）整节点删除。
- `render_preview()` 与 `render()` 共用同一条清洗流水线，只跳过图片转存 —— 预览过的排版就是发出去的样子。

## 三、图片流水线（只在 `render()` 执行）

单张：`download_url($_src, 30)` → `wp_get_image_editor()` → `resize(1080, null)` → `set_quality(82)` → 存临时 JPEG → 体积 > 900KB 再 `set_quality(70)` 存一次 → `YIMAI_GSO_Wx_Api::upload_content_image()` → 用返回的 url 覆盖 `src`。

| 参数 | 值 | 为什么 |
| --- | --- | --- |
| 超时 | 30s 下载 / 45s 上传 | 与 API 层上传超时对齐 |
| 最大宽度 | 1080 | 微信正文宽度的实际上限，再宽会被压扁 |
| 只缩不放 | 原图宽度 ≤ 1080 时跳过 resize | 放大只会变糊且体积变大 |
| 质量 | 82 → 70 | 82 是肉眼看不出损失的质量；仍超 900KB 再降一档 |
| 体积阈值 | 900KB | `uploadimg` 硬上限 1MB，留 100KB 余量给 multipart 头部 |
| 单篇上限 | 20 张 | 再多会把同步拖到超时；超出部分保留原 src 并告警 |

异常处理：

- **任何一张失败都不中断整篇**：替换成 `<p style="color:#94a3b8;font-size:14px">[图片未能转存：ALT 文字]</p>`，原因写进 `get_warnings()`。
- 图片被 `wpautop` 包在 `<p>` 里时（`<p><img></p>`），提示会替换**父级 `<p>`**；父级里还有文字则降级成 `<span>` —— 否则会出现 `<p><p>…</p></p>`，微信拆段后凭空多两个空行。
- 已经是微信图床（`qpic.cn` / `qlogo.cn`）的图片直接跳过，不浪费上传配额。
- 空 `src` 的 `<img>` 直接删掉。
- 临时文件（下载件 + 压缩产物）用完即 `unlink`。

## 四、链接与文末脚注

| 情况 | 处理 |
| --- | --- |
| `href` 为空或以 `#` 开头 | unwrap，只留文字 |
| 站内（host 与本站一致、含 `www.` 差异，或相对链接） | 换成 `<span style="color:#576b95;text-decoration:none">文字</span>` |
| 站外 | 同上换成 span，同时把 URL 收进脚注，并在 span **后面**追加 `[n]` 上标角标 |
| 同一 URL 出现多次 | 只收一次（按首次出现的位置编号） |

角标与脚注一一对应，两处的编号都是半角 `[n]`。

正文里（角标挂在 span **外面**，紧跟其后）：

```html
<span style="color:#576b95;text-decoration:none">这份研究</span><span style="font-size:12px;color:#576b95;vertical-align:super;margin-left:2px;line-height:0">[1]</span>
```

文末列表：

```html
<section style="margin-top:2em;padding-top:1em;border-top:1px solid #eee;font-size:13px;color:#94a3b8">
  <p style="margin:0 0 .4em;font-size:13px;color:#94a3b8;word-break:break-all">[1]这份研究：https://example.org/ref?id=9</p>
</section>
```

脚注列表追加在正文末尾（`<section>` 是 `#wx-root` 的最后一个子节点，不是包在最外层外面）；标题取链接文字并截断到 60 字；`word-break:break-all` 是必须的，长 URL 否则会被挤出屏幕。

> 为什么角标必须挂在 span 外面：span 带 `color:#576b95`，角标嵌进去会继承链接色、和文字连成一坨色块；挂在外面则各自独立。
> 为什么角标自己也是 span 而不是 `<sup>`：`<sup>` 会不会被微信保留属于**标签白名单**问题，本地拿不到 AppID、站点也不在本机，发出去之前无法验证；span + 内联 `vertical-align:super` 走的是已验证的那条样式路径。
> 编号口径：同一 URL 只编一个号（正文出现两次都是 `[1]`，文末只有一条）；站内链接不进脚注，也就不带角标；编号每次 `render()` / `render_preview()` 从 1 重新开始 —— 用局部数组而不是静态属性，否则第 3 篇文章的脚注会从 `[7]` 起跳。

## 五、代码块

`<pre>` 内部不再按 HTML 处理，而是收成纯文本后整体转义：

1. 文本子节点直接取 `nodeValue`；
2. `code` 子元素当容器（core/code 区块、高亮插件都会包一层），递归取其文字；
3. `code` 内部的 inline 元素（`span` / `b` / `i` / `em` / `strong` / `a` / `mark` / `u` …）同样当容器 ——
   高亮插件插的 `<span class="k">` 是渲染噪音，露出字面标签会毁掉整块代码；
4. 其它元素（`div` / `p` / `ul` / `table` / `h1-h6` …）说明作者在 `pre` 里裸写了标签（没转义），
   被解析器变成了真实元素 —— 用 `saveHTML` 还原成源码字样；这条线按「高亮器不产出块级标签」划：
4. 清空 `pre` 子节点，写入单个文本节点：先 `htmlspecialchars` 保证任何 `<` 都不可能是标签起点，再交给 `appendXML` 把实体解析回字符，最后由 DOM 统一转义输出 `&lt;`
   （直接把 `htmlspecialchars` 的结果塞 `createTextNode` 会二次转义，输出成 `&amp;lt;`）。

结果：`<pre><code>&lt;div&gt;x&lt;/div&gt;</code></pre>` 和 `<pre><code><div>被解析成元素</div></code></pre>` 两种写法，最终都能看到 `<div>` 原文。

## 六、长度闸门与错误码

顺序：**先粗估拦超长（不碰图片）→ 再精确算最终结果**。两道闸用的是同一个字数口径（`wp_strip_all_tags` 后的字符数），前置那道只是提前拦截明显超标的文章，避免为注定失败的文章上传图片、消耗 uploadimg 日配额。前置那道不做字节判断：原文里作者的标记（`class` / `data-*`）会让原始 HTML 远比清洗后更大，拿原始字节数比较会误杀正常文章。

| 条件 | WP_Error code | message |
| --- | --- | --- |
| 正文为空（`the_content` 返回空串） | `wx_empty` | 正文是空的，没有内容可以同步到草稿箱 |
| 解析前纯文本 > 20000 字（粗估闸） | `wx_too_long` | 正文超过 20000 字，微信拒收，请拆分为上下篇 |
| 清洗后纯文本 > 20000 字（精确闸） | `wx_too_long` | 正文超过 20000 字，微信拒收，请拆分为上下篇 |
| HTML > 1MB（精确闸） | `wx_too_big` | 正文超过 1MB，请减少内联图片 |
| 清洗后既无文字也无图片 | `wx_empty` | 正文清洗后没有可显示的内容（只剩脚本或空段落），请检查文章内容 |
| DOM 解析不出根节点 | `wx_render` | 正文解析失败（HTML 结构无法识别），请检查文章里是否有未闭合的标签 |
| 入参不是文章对象 | `wx_render_input` | 没有拿到文章内容，无法生成公众号正文 |

返回值契约：**要么返回完整可提交的 string，要么返回 `WP_Error`，任何分支都不会返回空字符串**（上层可以直接 `is_wp_error()` 判定，不用再猜空值）。
纯图片的图集文章是合法内容，不会被判空 —— 只有「连一张 `<img>` 都没有、且没有任何文字」才算空。

## 七、已知取舍

1. **作者 style 全部丢弃**：只按标签重建。保留作者 `text-align` / `color` 会更「忠实」，但 `float` / `width` / `position` 在手机上必然翻车，统一丢弃的行为可预测。
2. **`pre > code` 会被拍平成 `pre`**：代码块不再有 `<code>` 的粉色底纹（那是行内代码样式），换来的是缩进与换行绝不丢。
3. **预览不转存图片**：`render_preview()` 保留原 src，浏览器能显示，微信不能 —— 预览看的是排版，不是「发出去能不能显示」。
4. **正文角标与文末编号严格一一对应**：同一 URL 复用同一编号（不会出现两条一样的脚注），站内链接不加角标；编号只在本篇内有效。
5. **角标用 span 而不是 `<sup>`**：`<sup>` 依赖微信的标签白名单，本地无法验证（没有 AppID、站点不在本机），而它掉不掉是「发出去才看得见」的问题；span + 内联 `vertical-align:super` 走已验证的样式路径，视觉几乎无差别。
6. 超过 20 张图时，第 21 张起保留原外链（在微信里就是白框），同时给一条告警，由同步器决定是否拦下这篇。
