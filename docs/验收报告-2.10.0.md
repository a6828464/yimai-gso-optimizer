## 4. 验包方法与命令（可独立复现）

### 4.1 为什么不能用 `grep 中文文件名` / `unzip -l`

- **tar/zip 里的中文是八进制转义**：`git archive --format=tar HEAD | tar -t | grep 调研与实施方案` 输出 **0**，但该文件其实在包里（路径形如 `docs/\345\205\254\344\274\227\345\217\267...`）。用 grep 判断「在不在包里」会得到**假通过**。
- **macOS 自带 Info-ZIP 6.00 不认 0x800 UTF-8 标志位**，`unzip -l` 即使设 `LANG` 也乱码。
- **git 侧同源坑**：`git ls-tree --name-only` 默认 `core.quotePath=true`，非 ASCII 路径同样输出 `\345...`；两边都被转义时「看起来一致」，实际无法比对。

### 4.2 三条差集断言

```bash
# 树清单：必须关闭 quotePath
git -C "$PLUGIN" -c core.quotePath=false ls-tree -r --name-only HEAD > tree.txt

# 包清单：用 python zipfile 解码，并过滤目录条目
python3 -c "import sys,zipfile;print('\n'.join(sorted(n for n in zipfile.ZipFile(sys.argv[1]).namelist() if not n.endswith('/'))))" pkg.zip > pkg.txt
```

- **A. `pkg ⊆ tree`**：包里不许有树里没有的幽灵文件（防止「多打进一个不该发的文件」）。
- **B. `tree − pkg == 期望排除集`**，且**恰好相等**（两个方向都查：少排 = 漏出去；多排 = 误排）。计数相等不算通过——少一个 + 多一个会互相抵消。
- **C. 期望排除集显式枚举**，不推导：`tools/release.sh`、`docs/公众号同步-调研与实施方案.md`。（目录规则 `tools/ export-ignore` 会展开成 N 个文件，用「规则条数」推导必错。）

本版实测：

```

[A] 通过   [B] 恰好相等   [C] 显式枚举命中
```

### 4.3 commit 前后的口径差异

`git archive` 读的是**被归档那棵树**里的 `.gitattributes`，不是工作区。所以：

- 提交后验包：`git archive --format=zip --output pkg.zip HEAD`
- 提交前自查：`git archive --worktree-attributes …`（读工作区规则）

本版曾出现过的真实状态：规则只在工作区时，`HEAD` 口径下方案书仍在包里（61→71 文件差集暴露），`--worktree` 口径下才是 70。**这正是「必须提交后再验」的原因。**
