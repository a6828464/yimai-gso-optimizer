# 后台移动端修复记录（responsive.css 覆盖层）

> 适用版本：2.10.0 · 责任范围：`admin/css/responsive.css` + 本文件
> 修复对象：插件**已有页面**在手机端（375px，微信内置浏览器 / iPhone SE）的显示问题。
> 用户原话：「gos 的插件ui 在手机端显示非常不友好」—— 这是历史问题，不是新功能带来的。

---

## 0. 一句话结论

老页面在 375px 下的横向溢出、表格挤压、按钮点不中、12px 小字四个问题已经清零；
**没有改 `admin.css`（9681 行）和 `panels.css`（2352 行）一个字节**，全部规则写在
`admin/css/responsive.css` 的 19 个媒体查询里，桌面端（≥1201px）渲染结果与改动前逐像素一致。

### 验收结果（实测）

| 视口 | 页面横向滚动 | 内容区内部横向滚动 | 溢出元素 | 可点目标 <44px | 正文 <14px |
|---|---|---|---|---|---|
| 375×667 | 0 | 0 | 0 | 0 | 0 |
| 414×896 | 0 | 0 | 0 | 0 | 0 |
| 800（平板/分屏） | 0 | 0 | 0 | 22\* | 0 |
| 960 | 0 | 0 | 0 | 22\* | 0 |
| 1024 | 0 | 0 | 0 | 29\* | 0 |
| 1440（桌面） | 0 | 0 | 0 | 41\* | 0 |

\* 可点目标的 44px 规则**只在 ≤782 生效**（手机档）。783~1024 是平板/分屏宽度，
WordPress 自己那一档也是 40px，本层不接管，避免把平板界面撑肿。手机档（375/414）是 0。

桌面零影响是**实测**过的：同一份 DOM 在 1440px 下，加载 / 不加载 `responsive.css`
两种情况的几何指纹（427 个元素的 left/top/width/height 加权哈希）完全相同：
`1948168515/427` = `1948168515/427`。

## 1. 修复方法（为什么这么做）

### 1.1 只写覆盖层，不动源样式表

`admin.css`（9681 行）和 `panels.css`（2352 行）是 50 多个页面共用的历史样式，
改一条 `padding` 会连锁影响其它页面，回归成本极高。所以本轮所有修复都是
**在 responsive.css 里、只在媒体查询内**重新声明，靠「加载顺序最后 + 必要时同权重」
赢下冲突。代价是选择器要写得更长，收益是**删掉这个文件就 100% 回到改动前**。

### 1.2 每条规则都限定在媒体查询内

`responsive.css` 顶层只有 `:root`（断点常量），业务规则全部在
`@media (max-width: 1200/960/782/480px)` 里。这一点有静态校验脚本可复跑（见 §5）。

### 1.3 `!important` 只有三类来源（文件头也写了）

| 类型 | 场景 | 例子 |
|---|---|---|
| ① | `admin.css` 原声明自己带 `!important`，不同权重根本覆盖不了 | `.yimai-gso-layout > .yimai-gso-panel { width:auto !important }`、`.yimai-gso-btn-modern-* { min-height:44px !important }` |
| ② | 目标样式来自**页面内联 `<style>`**，它在文档里排在本文件之后 | `.ymwx-*`（微信分享卡片页）、`.yimai-kb-stats`（品牌资料页） |
| ③ | 目标样式来自 `style=""` **内联属性** | `.yimai-gso-layout[style*=grid-template-columns]`、`#yimai-gso-rw-paste-clear`、`[style*="font-size:12px"]` |

每处 `!important` 旁边都标了属于哪一类；不属于这三类的一律不加（文件里已经清理过一轮）。

### 1.4 断点只用四档

`1200 / 960 / 782 / 480`，与 `components.css`、`docs/UI组件规范.md` 同一套。
782 是 WordPress 后台自己折叠左侧菜单的分界，跟它对齐才不会出现
「菜单已折叠、卡片还是四列」的畸形中间态。

### 1.5 测试方法（可复跑）

没有本地 WordPress，所以用「真实 CSS + 真实结构」的静态夹具：

1. 把四份真实 CSS（admin → panels → components → responsive）按线上顺序引入；
2. 把老页面的**真实标记**（从 `includes/class-admin.php` 抄出来的结构，含内联 `style`），
   按页面分块放进夹具，页面内联 `<style>`（`.ymwx-*` / `.yimai-kb-stats`）也照线上
   顺序放在插件样式**之后**，用来验证「②类 !important 是否必要」；
3. 用无头浏览器在两个宽度的 iframe 里渲染（iframe 视口 = 真实媒体查询），
   脚本自动量四件事：`documentElement.scrollWidth`、内容区内部滚动、
   越界元素、可点目标高度（用 `offsetHeight`，避开入场动画 `scale(.95)` 的干扰）、
   叶子文本字号。

夹具和脚本是临时的（`/tmp`），不进仓库、不进发布包；本文件 §4 记录了每一块的
数据来源，方便以后用同样方法回归。

## 4. 验收：怎么复跑

```bash
# 1) 结构：所有规则必须在媒体查询内（顶层只允许 :root）
python3 - <<'PY'
import io, re
src = io.open('admin/css/responsive.css', encoding='utf-8').read()
css = re.sub(r'/\*.*?\*/', '', src, flags=re.S)
depth, top, buf, media = 0, [], '', 0
for ch in css:
    if ch == '{':
        sel = buf.strip().split('\n')[-1].strip()
        if sel.startswith('@media'): media += 1
        elif depth == 0: top.append(sel)
        depth += 1; buf = ''
    elif ch == '}': depth -= 1; buf = ''
    else: buf += ch
print('media:', media, '| top-level:', top, '| balanced:', depth == 0)
PY
# 期望：media: 19 | top-level: [':root'] | balanced: True

# 2) 手机档：真实 CSS + 真实结构夹具，无头浏览器量五个指标
#    documentElement.scrollWidth - clientWidth == 0
#    内容区 .yimai-gso-main-content 的 scrollWidth - clientWidth == 0
#    越界元素 0；可点目标（offsetHeight）<44 的 0；叶子文本 <14px 的 0
#    375×667 与 414×896 两个宽度都要过

# 3) 桌面零影响：1440px 下加载/不加载 responsive.css，几何指纹必须相同
```

浏览器里最快的手工验收路径：开 DevTools 设备模拟 → iPhone SE（375×667）→
逐个点开左侧标签，横向拖动页面看是否出现整页滚动条；再点一遍按钮看是否有小于
手指宽度的目标。**判定标准：整页不横滚（表格在卡片内部横滚是预期行为）。**

## 5. 遗留问题 / 后续建议

1. **表格 wrapper 还没补**（见 §3 清单）。CSS 兜底能让表格可用，但「父容器横滚」
   意味着表头会跟着一起滑走；补上 `.yimai-gso-table-wrap` 后可以把表头做成 sticky。
2. **内联样式是主要技术债**。本轮有 6 条规则靠 `[style*="..."]` 属性选择器工作
   （改写页双栏、llms 页 300px 栅格、两处文字按钮、小字兜底）。谁把那些内联样式
   换成类名，就要回来删掉对应规则，否则规则会「静默失效」。
3. **`admin.css` 5319 行那条 `width:100% !important` 应该改掉**（改成
   `box-sizing:border-box` 或干脆删掉）。现在靠覆盖层压住，属于「治标」。
4. **动效**：`.yimai-gso-404-modal-in` 等入场动画是 `scale(.95)`，量高度时必须用
   `offsetHeight`，用 `getBoundingClientRect` 会得到 41.8px 这种假数据。
5. **图片库工具栏**改成每控件一行的代价是工具栏变高；如果以后想要「一行两个」，
   需要先给 `.yimai-gso-ilib-toolbar-right` 加 `flex-wrap` 并去掉内联宽度。
6. **没有真机验证**。本轮用无头浏览器 + 真实 CSS 量的；微信内置浏览器（X5/WKWebView）
   的字体渲染会让行高略有出入，建议发布前在真机过一遍「仪表盘 / 内容管理 / SEO推送 /
   404 优化」四页。
7. **不改源文件是硬约束**，所以本文件里所有 `!important` 都是「借来的权重」；
   如果哪天有人重排了 `admin.css` 的层叠顺序，需要重新跑 §4。
